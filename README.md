# 🌐 FileManager 4.0 — Веб-панель управления сервером AmneziaWG (2.0 / 3.1)

**FileManager 4.0** — это современная, легковесная и отказоустойчивая веб-панель (DevOps-комбайн) для полного цикла управления VPN-сервером на базе ядерного модуля **AmneziaWG** (автор базовых скриптов инсталлятора — `@bivlked`), локальным DNS-фильтром **AdGuard Home**, правилами межсетевого экрана **UFW / Iptables** и системными службами.

Панель спроектирована так, чтобы сочетать удобство графического интерфейса (GUI) с максимальной производительностью нативного модуля ядра Linux (DKMS) без накладных расходов Docker-контейнеров.

## ✨ Ключевые возможности

* 📊 **Живой Дашборд:** Мониторинг нагрузки сервера (CPU, RAM, Uptime, Диск), подсчет общего трафика, текущей скорости (Rx/Tx) и интерактивные графики истории за последний час (общий и по каждому клиенту отдельно).
* 👥 **Управление клиентами VPN:**
  * Одиночное и массовое (Bulk до 50 шт. с выгрузкой в `.zip`) создание конфигураций.
  * Поддержка временных клиентов (`--expires`: `1d`, `7d`, `30d`) с автоматическим удалением через `cron`.
  * Шейпер трафика (установка лимитов скорости в Мбит/с для конкретного IP клиента на лету через `tc`).
  * Сортировка клиентов по имени, статусу активности (`Активен`, `Недавно`, `Неактивен`), объему трафика и текущей скорости.
* 🌐 **Сеть, Конфигурация AWG и Фаервол:**
  * Встроенный редактор серверного конфига `awg0.conf` с функцией **автоматического бэкапа** перед каждым сохранением.
  * Визуальное управление правилами `UFW` (открытие/удаление портов по интерфейсам и протоколам) и таблица прослушиваемых портов (`ss -tunlp`).
* ⚙️ **Службы и DNS (AdGuard Home):**
  * Перехват и перенаправление всего DNS-трафика (`UDP/TCP 53`) клиентов туннеля на локальный AdGuard Home через `iptables DNAT` + блокировка обходного DoT (`TCP 853`).
  * Интеграция с API AdGuard Home для отображения статистики запросов и заблокированной рекламы прямо в панели.
  * Быстрый перезапуск системных служб (`AdGuardHome`, `nginx`, `sshd`, `mtproxyl-telemt`).
* 🛡️ **Защита и Гео-фильтрация:**
  * Изоляция RU-трафика в один клик (блокировка российских подсетей внутри VPN через `ipset` + `iptables` с автообновлением баз по расписанию `cron`, чтобы запросы к RU-ресурсам не шли с зарубежного IP сервера).
* 📥 **Автономный установщик модулей (Stateful Installer):**
  * Установка **AmneziaWG** прямо из браузера с тонкой настройкой пресетов, портов, маршрутов и автоматическим возобновлением после системных перезагрузок (`reboot`).
  * Тихая установка **AdGuard Home** с автоматическим разрешением конфликта портов (`3000` -> `3001`).
  * Интеграция команды установки прокси **MTProto (MEKO)**.
* 💾 **Бэкапы и Автообновление:** Полный дамп всех настроек сервера и панели в `.tar.gz` архив в один клик, восстановление из архива и обновление кода панели напрямую с GitHub.

## 🚀 Быстрый старт и установка

### Вариант 1: Автоматическая установка (Рекомендуется)
Если у вас чистый сервер, используйте штатный скрипт развертывания репозитория:
```bash
apt update && apt install -y curl git
git clone https://github.com/makar19977v-glitch/servpanel.git /root/servpanel
cd /root/servpanel
chmod +x install.sh
sudo ./install.sh
```

### Вариант 2: Ручное развертывание по шагам
1. **Клонируйте репозиторий и установите зависимости:**
   ```bash
   cd /root
   git clone https://github.com/makar19977v-glitch/servpanel.git
   cd servpanel
   npm install
   ```
2. **Запустите панель через PM2 (слушает локальный порт `3000`):**
   ```bash
   pm2 start server.js --name "awg-admin"
   pm2 save
   pm2 startup
   ```
3. **Настройте Nginx (внешний порт `4444` -> внутренний `3000`):**
   Убедитесь, что в `/etc/nginx/sites-available/awg-admin` настроен `proxy_pass http://127.0.0.1:3000;` на порту `4444` (с SSL или базовой защитой).
4. **Пароль по умолчанию:**
   При первом запуске пароль берется из файла `/root/servpanel/admin_pass.txt` (если файла нет, пароль по умолчанию: `admin123`). Сразу смените его в верхней панели интерфейса по кнопке **«🔑 Сменить пароль»**.

## 🛠️ Как это работает (Архитектура и безопасность)

1. **Двухуровневая сетевая схема (`4444` -> `3000`):**
   Бэкенд панели (`server.js`) работает строго локально на порту `3000`. Внешние подключения принимает **Nginx** на порту `4444`. Это защищает Node.js от прямого воздействия из интернета и позволяет привязать SSL-сертификаты домена.
2. **Персистентная авторизация (`HMAC-SHA256`):**
   При входе в панель генерируется криптографический токен (`crypto.createHmac`) на основе секретного ключа и пароля, который сохраняется в `httpOnly` cookie `awg_auth` сроком на 30 дней. Даже если сервер перезагрузится 3 раза подряд во время установки модулей или перезапустится процесс `PM2`, **ваша сессия в браузере не слетит**, и терминал логов продолжит работу без ошибки `401 Unauthorized`.
3. **Защита от самоблокировки фаерволом (`PANEL_PORT`):**
   Штатный установщик AmneziaWG включает жесткую политику UFW `deny incoming`. Чтобы вы не потеряли доступ к веб-панели, `server.js` при запуске любой установки передает переменную `PANEL_PORT="4444"` в bash-обертку. Скрипт принудительно открывает порт `4444/tcp` (а также `80`, `443`, `22`, `2233`) в UFW **до** и **после** работы инсталлятора.
4. **Механизм выживания при перезагрузках (Stateful Resume):**
   Полная установка AmneziaWG требует до 2–3 перезагрузок сервера (обновление ядра, применение `sysctl`, загрузка модуля `DKMS`). Обертка `install_awg_stateful.sh`:
   * Сохраняет все выбранные вами в веб-интерфейсе флаги в `/root/awg_install_params.env`.
   * Копирует себя в `/root/awg_installer_wrapper.sh` и регистрирует временное задание в `/etc/cron.d/awg_resume` (`@reboot`).
   * После каждого ребута сервер сам запускает продолжение установки с того шага, на котором остановился (`/root/awg/setup_state`), транслируя лог в `/var/log/awg_install.log`.
   * По завершении (маркер `=== INSTALLATION DONE ===`) скрипт автоматически удаляет временные файлы и задачу `cron`.
5. **Разрешение конфликта портов с AdGuard Home:**
   По умолчанию установщик AdGuard Home пытается занять порт `3000` для первичной веб-настройки, на котором уже сидит наша панель. Скрипт `install_adguard_silent.sh` заранее создает конфигурацию `/opt/AdGuardHome/AdGuardHome.yaml` с привязкой к порту `3001` (или оставляет `3000`, если внутренний порт панели изменен) и открывает его в UFW.
6. **Аудит безопасности и Авто-бэкапы конфига:**
   * Любое важное действие (вход, неверный пароль, выход, удаление клиента, правка конфига, запуск установки) записывается с IP-адресом и таймстампом в `/var/log/awg_audit.log`.
   * При сохранении конфига AWG через веб-редактор старый файл автоматически копируется рядом с именем `awg0.conf.bak_<timestamp>`.

## 🔬 Полный справочник параметров обфускации

Обычный WireGuard мгновенно вычисляется системами DPI (ТСПУ) по двум признакам: **фиксированным размерам пакетов рукопожатия** и **фиксированным 4-байтным заголовкам типа сообщения** (`0x01`, `0x02`, `0x03`, `0x04`). AmneziaWG полностью разрушает эти сигнатуры.

Все параметры ниже генерируются автоматически при установке, прописываются в `/root/awg/awgsetup_cfg.init` и в секцию `[Interface]` серверного конфига `/etc/amnezia/amneziawg/awg0.conf`.

### 1. Мусорные пакеты (Junk Packets): `Jc`, `Jmin`, `Jmax`
Перед началом настоящего криптографического рукопожатия инициатор отправляет серию случайных UDP-пакетов («пустышек»), чтобы сбить с толку потоковые анализаторы DPI.
* **`Jc` (Junk Count):** Количество мусорных пакетов перед рукопожатием.
  * *Диапазон:* `0–128` (`0` — отключает отправку). В пресете `default`: `3–6` (случайно), в пресете `mobile`: строго `3`.
* **`Jmin` (Junk Min Size):** Минимальный размер одного мусорного пакета в байтах.
  * *Диапазон:* `0–1280`. В `default`: `40–89` байт, в `mobile`: `30–50` байт.
* **`Jmax` (Junk Max Size):** Максимальный размер мусорного пакета в байтах (должен быть $\ge Jmin$).
  * *Диапазон:* `0–1280`. В `default`: $Jmin + (50..250)$ байт, в `mobile`: $Jmin + (20..80)$ байт.
* 🔄 **Обязаны ли совпадать на сервере и клиенте?** **НЕТ.** Это односторонние пакеты-обманки, принимающая сторона их просто отбрасывает. Вы можете менять их на клиенте в любой момент без правки сервера.

---

### 2. Префиксный паддинг пакетов (Message Padding): `S1`, `S2`, `S3`, `S4`
К каждому служебному и информационному пакету WireGuard в самое начало дописывается блок случайных байтов заданной длины. Это меняет стандартный размер пакета и сдвигает заголовок типа сообщения вглубь пакета.
* **`S1` (Init Padding):** Паддинг пакета инициации рукопожатия (*Handshake Initiation*).
  * *Диапазон при генерации:* `15–150` байт.
* **`S2` (Response Padding):** Паддинг ответного пакета рукопожатия (*Handshake Response*).
  * *Диапазон при генерации:* `15–150` байт.
  * *Математическое ограничение:* Строго выполняется условие $S1 + 56 \neq S2$, чтобы итоговые размеры пакетов *Init* и *Response* никогда не совпали.
* **`S3` (Cookie Padding — появилось в AWG 2.0):** Паддинг пакета защиты от перегрузки (*Cookie Reply*).
  * *Диапазон при генерации:* `8–55` байт.
  * *Математическое ограничение:* Строго выполняется условие $S3 \neq S2 + 28$, чтобы размеры *Response* и *Cookie* не совпали.
* **`S4` (Data Padding — появилось в AWG 2.0):** Паддинг каждого пакета с пользовательскими данными (*Transport Data*).
  * *Диапазон при генерации:* `4–27` байт.
* 🔄 **Обязаны ли совпадать на сервере и клиенте?** **ДА, СТРОГО ОБЯЗАНЫ!** Принимающая сторона отсчитывает смещение, равное своему значению `S`, чтобы прочитать заголовок пакета. Если `S1–S4` отличаются хотя бы на 1 байт — пакет не будет опознан, связь оборвется на 100%.

### 3. Подмена заголовков типов сообщений (Magic Headers): `H1`, `H2`, `H3`, `H4`
В стандартном WireGuard первые байты пакета всегда равны `1`, `2`, `3` или `4`. AmneziaWG заменяет их на произвольные 32-битные числа (`uint32` в диапазоне от `5` до `2147483647`). В версии **AWG 2.0** они задаются **диапазонами** (`нижняя_граница-верхняя_граница`), и при отправке каждого пакета число выбирается из диапазона случайно!
* **`H1`:** Идентификатор пакета *Handshake Initiation* (пример в 2.0: `134567-245678`).
* **`H2`:** Идентификатор пакета *Handshake Response* (пример в 2.0: `3456789-4567890`).
* **`H3`:** Идентификатор пакета *Cookie Reply* (пример в 2.0: `56789012-67890123`).
* **`H4`:** Идентификатор пакетов данных *Transport Data* (пример в 2.0: `456789012-567890123`).
* ⚠️ **Критические особенности:**
  1. Диапазоны `H1`, `H2`, `H3` и `H4` **ни в коем случае не должны пересекаться** между собой (иначе приемник перепутает тип пакета).
  2. В профиле **AWG 3.1** значения `H1–H4` оставляются равными `1`, `2`, `3`, `4`, так как сам заголовок полностью шифруется ключом `HeaderProtectionKey`.
  3. На старых прошивках роутеров (например, Keenetic Speedster 5.0.6), которые не понимают дефис в `H1-H4`, диапазоны можно заменить на одиночные числа.
* 🔄 **Обязаны ли совпадать на сервере и клиенте?** **ДА, ОБЯЗАНЫ БЫТЬ ОДИНАКОВЫМИ (совместимыми)!** Отправитель берет число из своего диапазона, а приемник проверяет, входит ли оно в его диапазон.

### 4. Маскировка под легитимные протоколы (CPS — Concealment Packets): `I1` – `I5`
Специальные пакеты маскировки (*Special Handshake Packets*), которые отправляются перед рукопожатием и имитируют структуру реальных сетевых протоколов (DNS, QUIC/HTTP3, STUN, SIP). Это главная защита от фильтрации по «белым спискам протоколов» на мобильных сетях и блокировок зарубежных хостингов (Hetzner, OVH, DigitalOcean) по номеру автономной системы (AS).
* **`I1`:** Основной пакет CPS-маскировки. По умолчанию установщик генерирует пакет длиной `70–128` байт, который **байт-в-байт повторяет форму валидного DNS-ответа** (с доменом вроде `icloud.com` или `cloudflare.com`).
* **`I2`, `I3`, `I4`, `I5`:** Дополнительные опциональные пакеты CPS-цепочки (по умолчанию не задаются, но если вписать их в `awg0.conf`, скрипт `manage regen` автоматически перенесет их во все клиентские конфиги).
* **Синтаксис тегов конструктора CPS (`I1–I5`):**
  * `<r N>` — сгенерировать `N` криптографически случайных байт. *(Например, `<r 2>` в начале DNS-пакета создает уникальный 2-байтный Transaction ID для каждого подключения).*
  * `<b 0xHEX>` — вставить статическую последовательность байт в шестнадцатеричном формате (заголовки DNS/QUIC, SNI домена).
  * `<rc N>` — сгенерировать `N` случайных ASCII-букв/цифр.
  * `<rd N>` — сгенерировать `N` случайных десятичных цифр.
  * `<t>` — вставить текущую 4-байтную временную метку (Unix timestamp).
  * `<c>` — вставить 4-байтный счетчик пакетов.
* **Практический пример `I1` (имитация DNS-ответа):**
  ```ini
  I1 = <r 2><b 0x8580000100010000000025><rc 37><b 0x0463646e730669636c6f756403636f6d0000010001c00c00010001000003840004524b6bc2>
  ```
  > 💡 **Важно:** Префикс `<r 2>` в начале DNS-паттерна трогать нельзя! Без этих двух байт весь пакет сдвинется, перестанет распознаваться анализатором ТСПУ как DNS, а сам пакет станет статичным для всех пользователей.
  > 💡 **Совместимость с macOS и Мегафон:** Некоторые старые десктопные клиенты на macOS зависают при наличии `I1`, а в некоторых регионах Мегафона помогает удаление `I1` или замена на QUIC-мимикрию (генерируется через *Mini QUIC Generator* под разрешенный SNI, например `7-zip.org` для серверов Hetzner).
* 🔄 **Обязаны ли совпадать на сервере и клиенте?** **НЕТ.** Как и `Jc`, пакеты `I1–I5` отправляет инициатор, а вторая сторона их игнорирует.

### 5. Параметры третьей линии (AmneziaWG 3.0 / 3.1)
Доступны при выборе **Версии 3.1** в панели (на ядрах $\ge 6.7$):

| Параметр | Описание и механика работы | Обязан совпадать? |
| :--- | :--- | :---: |
| **`HeaderProtectionKey`** | 32-байтный ключ (Base64) для полного шифрования заголовков пакетов алгоритмом **ChaCha20**. Делает невозможным определение типа пакета.<br>⚠️ **Критическое требование:** Для работы этого ключа параметры `S1–S4` обязаны быть **не меньше `12`** (первые 12 байт `S`-паддинга используются как криптографический *nonce*). | **ДА, СТРОГО!**<br>*(При несовпадении — 100% отказ рукопожатия без текста ошибки)* |
| **`ContentPaddingAddition`** | Добавочный случайный паддинг **внутри зашифрованной части** пакета данных. Задается числом или диапазоном `lo-hi` (по умолчанию в 3.1: `32-128`). Скрывает реальный размер передаваемых данных. | **НЕТ** |
| **`RekeyAfterTime`**<br>**`RekeyTimeout`**<br>**`RejectAfterTime`**<br>**`KeepaliveTimeout`**<br>**`MaxHandshakeAttempts`** | Рандомизация таймингов протокола (принимают диапазон `lo-hi`, например `KeepaliveTimeout = 20-30`). Убирает фиксированные интервалы пересогласования ключей и keepalive-пакетов, по которым DPI мог косвенно вычислять длительные сессии WireGuard. | **НЕТ** |
| **`DisableCookies`** *(3.1)* | Односторонний флаг (`true/false`). Отключает отправку сервером пакетов Cookie Reply, убирая этот тип сообщений с провода (но снижает защиту от DDoS-флуда рукопожатиями). По умолчанию выключен. | **НЕТ** |
| **`RandomTrailers`** *(3.1)* | Двусторонний флаг дописывания случайного хвоста к пакетам рукопожатия.<br>⛔ **НЕ ВКЛЮЧАТЬ ВРУЧНУЮ!** В текущем релизе модуля сочетание `RandomTrailers` с параметрами `S4` и `H1-H4` вызывает известный баг падения скорости в ~100 раз (до 0.1 МБ/с). Установщик его намеренно не включает. | **ДА** |

> ⚠️ **Важный технический нюанс ядра AWG:** Если вы решите вручную **удалить** какой-либо параметр обфускации (например, `I1` или `HeaderProtectionKey`) из конфига в веб-редакторе панели, простой `awg syncconf` его не снимет (для AWG-параметров он работает только на добавление/изменение). Но **кнопка «💾 Сохранить и перезапустить AWG» в нашей панели делает полный `systemctl restart awg-quick@awg0`**, что гарантированно пересоздает интерфейс с чистого листа!

## 🎛️ Рекомендованные настройки панели и сценарии установки

При переходе во вкладку **«📥 Установка Модулей» -> AmneziaWG** используйте следующие проверенные комбинации настроек в зависимости от ваших задач:

### Сценарий А: «Универсальный стандарт» (Для дома, ПК, телефонов и роутеров)
* **Версия протокола:** `Версия 2.0 (Стабильная)` — гарантирует, что подключатся любые устройства, включая роутеры Keenetic/OpenWrt и старые приложения.
* **Профиль обфускации:** `Стандартный (default)`
* **Режим маршрутизации (IPv4):** `Весь трафик (0.0.0.0/0)` — классический полный туннель (корректно работает раздельное туннелирование внутри самого приложения Amnezia VPN).
* **Настройки IPv6:** `Отключить (disallow)` — выключает IPv6 на хосте, а клиентам в `AllowedIPs` дописывает заглушку `::/0`, чтобы трафик с телефонов (например, YouTube) не утекал мимо VPN по IPv6 мобильного оператора.
* **UDP Порт:** `39743` (или оставьте пустым).

### Сценарий Б: «Жесткий мобильный DPI / ТСПУ» (МТС, Мегафон, Tele2, Yota)
Если VPN берется преимущественно для смартфонов в сотовых сетях РФ:
* **Версия протокола:** `Версия 3.1 (Последняя)` (только если на телефонах стоит свежий Amnezia VPN `>= 5.0.1.5` или AmneziaWG `>= 3.1.4`) либо `Версия 2.0`.
* **Профиль обфускации:** `Мобильный (mobile)` — фиксирует `Jc = 3` и сужает размер мусорных пакетов (`Jmin = 30–50`, `Jmax = Jmin + 20..80`), чтобы сотовый оператор не сбрасывал сессию из-за фрагментации и оверхеда.
* **UDP Порт:** **`443`** — критически важно для мобильных сетей! Многие операторы режут нестандартные UDP-порты, но свободно пропускают `443/udp`, принимая его за стандартный трафик протокола QUIC / HTTP3.

### Рекомендации по чекбоксам (галочкам) в карточке установки:
1. ✅ **Изолировать клиентов друг от друга (`isolation=on`)** — **ВКЛЮЧИТЬ.** Добавляет правило `iptables -I FORWARD -i awg0 -o awg0 -j DROP`. Клиенты внутри VPN не смогут сканировать и пинговать устройства друг друга. Выключайте только если вам нужна локальная сеть между пирами.
2. ✅ **Сохранить системные пакеты (`snapd` и др. / `--keep-packages`)** — **ОБЯЗАТЕЛЬНО ВКЛЮЧИТЬ!** Без этой галочки оригинальный скрипт в режиме `--yes` принудительно вычищает из системы `snapd`, `lxd` и каталоги `/var/snap`, что может удалить ваши сторонние контейнеры или службы.
3. ⬜ **Без UFW, Fail2Ban и оптимизаций (`--no-tweaks`)** — **ОСТАВИТЬ ВЫКЛЮЧЕННОЙ (пустой).** Позволяет скрипту включить алгоритм ускорения TCP **Google BBR**, увеличить сетевые буферы ядра под объем вашей RAM, выставить `MTU = 1280` с автоматическим `TCP MSS-clamp (1240)` (спасает от зависания страниц на мобильных сетях) и настроить защиту SSH от брутфорса через **Fail2Ban**. За сохранность порта панели (`4444`) отвечает наша встроенная защита.

## 🔧 Полезные команды для диагностики по SSH

Если вам нужно быстро проверить статус сервисов прямо из консоли сервера:

```bash
# Проверить статус процесса веб-панели и посмотреть её логи
pm2 status
pm2 logs awg-admin --lines 30

# Узнать точную версию утилит и загруженного в ядро модуля AmneziaWG
awg --version
cat /sys/module/amneziawg/version

# Проверить статус интерфейса AWG и активные рукопожатия пиров
sudo systemctl status awg-quick@awg0
sudo awg show

# Запустить встроенную самодиагностику AWG (проверка модуля, sysctl, портов)
sudo bash /root/awg/manage_amneziawg.sh check
sudo bash /root/awg/manage_amneziawg.sh diagnose

# Посмотреть журнал аудита безопасности веб-панели
cat /var/log/awg_audit.log
```
