# Обновление Servpanel до 2.4.1

> **Что нового в 2.4.1:** исправлен вход через Nginx на нестандартном порту
> (`:4444`). Nginx с `Host $host` отбрасывал порт, а панель сравнивала `Origin`
> с портом. Теперь `install.sh` создаёт сайт с `Host $http_host`, а `upgrade.sh`
> безопасно исправляет эту строку в старом сайте панели. Если старый сервер уже
> обновлён вручную, повторно ничего менять не нужно.

Эта инструкция — для **уже работающей** панели 1.0.0 на ваших серверах
( RU `r1043423` и EN `r1172625` ). Она сохраняет всё, что было настроено до
обновления, и не трогает каскад.

> **Важно:** старую кнопку «Обновить с GitHub» в панели 1.0.0 **не нажимайте**.
> В ней зашит `git pull --ff-only || git reset --hard origin/main`, который может
> стереть файлы новой панели. Первое обновление делается один раз по SSH
> скриптом `upgrade.sh`; после него кнопка в панели уже безопасная.

---

## 1. Что было в диагностике

| Параметр | RU | EN |
|---|---|---|
| Панель | `/root/servpanel`, pm2 `awg-admin` | то же |
| Версия | 1.0.0 | 1.0.0 |
| Порт Node | 3000 (`.panel_port` нет) | 3000 |
| Nginx | проксирует на `127.0.0.1:3000` | то же |
| Данные панели | только `admin_pass.txt` | только `admin_pass.txt` |
| Клиенты / каскад | `awg0`, `awg1`, `amn0` в mangle | `awg0`, без каскада |

На RU `amn0` — это **docker-мост** (`172.29.172.0/24`), а не отдельный
AmneziaWG-туннель. Правила фильтрации для `amn0` и `awg0` уже стоят; обновление
их не переписывает. `awg-routing.sh`, `ipset`, `ip rule`, systemd-таймеры
каскада остаются как есть.

## 2. Первое обновление (по SSH, один раз)

### 2.1. Скопировать архив на сервер

С локального компьютера:

```powershell
scp C:\Users\Adm\Desktop\servpanel-fixed\servpanel-2.4.1.tar.gz root@<IP-сервера>:/root/
```

### 2.2. Проверить архив и распаковать

```bash
cd /root
sha256sum servpanel-2.4.1.tar.gz
# сверьте с файлом servpanel-2.4.1.tar.gz.sha256

mkdir -p /root/servpanel-2.4.1
tar -xzf /root/servpanel-2.4.1.tar.gz -C /root
ls -la /root/servpanel-2.4.1/upgrade.sh
```

### 2.3. Запустить безопасное обновление

```bash
bash /root/servpanel-2.4.1/upgrade.sh
```

Что произойдёт:

1. скрипт проверит `server.js`, `lib/`, `public/index.html`, `public/style.css`,
   `public/app.js` и наличие `admin_pass.txt`;
2. поставит зависимости во временный каталог (в релизе уже есть
   `node_modules`, поэтому npm/интернет не обязательны);
3. запустит новую версию на **копии данных** и отдельном порту (3998+)
   и проверит HTTP;
4. остановит `awg-admin`, сделает бэкап панели в
   `/root/backups/servpanel-pre-update-*.tar.gz` и снимок системных конфигов
   `system-config-*.tar.gz` (включая `/etc/amnezia/amneziawg`, `/root/awg` и
   `awg-routing.sh`; только для ручного восстановления);
5. заменит файлы кода, **не трогая** данные, `.git`, конфиги AWG, iptables,
   ipset, systemd, nginx, fail2ban и AdGuard;
6. запустит `pm2` и проверит `http://127.0.0.1:3000/` (или порт из
   `.panel_port`, если он задан);
7. при ошибке автоматически откатится из бэкапа.

В конце скрипт печатает новую версию, путь бэкапа и команду отката.
Полный журнал: `/var/log/servpanel_update.log`.

### 2.4. Открыть панель

```text
http://<IP-или-домен>/
```

Логин — `admin`, пароль — **тот же**, что был в старой панели
(`/root/servpanel/admin_pass.txt`). Сессии старого формата не переносятся,
поэтому нужно войти один раз заново. 2FA, если она была, продолжит работать
(файл `.users.json` не перезаписывается).

Проверьте:

* дашборд показывает клиентов и трафик;
* «Клиенты» — старые клиенты на месте, QR/`vpn://` открываются;
* «Каскад» — статус `awg0`/`amn0`/`awg1` и правила видны, ничего не
  перенастроено;
* «Обновление» — версия `2.4.1`, список бэкапов.

### 2.5. Если что-то пошло не так

```bash
# посмотреть журнал
tail -n 100 /var/log/servpanel_update.log

# состояние pm2
pm2 status
pm2 logs awg-admin --lines 80

# откат к бэкапу, созданному перед обновлением
bash /root/servpanel-2.4.1/upgrade.sh --rollback /root/backups/servpanel-pre-update-YYYYMMDD-HHMMSS.tar.gz
```

Если панель не отвечает, но SSH работает, откат можно сделать и вручную:

```bash
pm2 stop awg-admin
tar -xzf /root/backups/servpanel-pre-update-*.tar.gz -C /root
pm2 restart awg-admin --update-env
```

## 3. Второй сервер (EN)

Повторите те же шаги на EN-сервере. У него нет каскада, но панель и данные
обновляются так же. После обновления проверьте, что `awg0` и клиенты на месте.

> Не запускайте `upgrade.sh` с RU-сервера на EN по SSH «за компанию»:
> скрипт меняет только локальный `/root/servpanel`. Запускайте его на каждом
> сервере отдельно.

## 4. Как обновляться дальше (уже из панели)

Вкладка **«Обновление»**:

* **Файл** — загрузите новый `servpanel-*.tar.gz` (до 10 МБ). Это основной
  способ: панель сама проверит архив, сделает бэкап, заменит код и откатится
  при ошибке.
* **URL** — прямая ссылка на релиз (например, на вашем файловом сервере).
* **GitHub** — только если файлы панели совпадают с репозиторием и в них нет
  локальных изменений. Режим делает `git fetch` + `git merge --ff-only`,
  **без** `git reset --hard`. Если в панели есть локальные правки, он
  откажется работать и предложит установку из файла.
* **Откат** — кнопка у любого бэкапа в списке.

После обновления из файла GitHub-режим, скорее всего, будет недоступен:
файлы панели отличаются от `origin/main`. Это нормально, пока вы не
закоммитите новую версию в свой репозиторий.

## 5. Что сохраняется и что не меняется

Сохраняются:

* `admin_pass.txt`, `.secrets.json`, `.users.json`, `.sessions/`;
* `.obf_profiles.json`, `.notify.json`, `.backup.json`, `.backup_pass`,
  `.install_state.json`;
* `.panel_port`, `.panel_public_port`;
* `.git` (история репозитория);
* все клиенты, ключи, QR и `vpn://` в `/root/awg`;
* конфиги `/etc/amnezia/amneziawg/*.conf`;
* `/root/awg/awg-routing.sh`, iptables/ipset/ip rule;
* systemd-юниты каскада, nginx, fail2ban, AdGuard.

Не меняются автоматически:

* `awg1.conf` и маршруты каскада — только по явной команде в разделе «Каскад»;
* правила фильтрации `amn0`/`awg0` — обновление их не переписывает;
* настройки AdGuard и его фильтры.

Скрипт дополнительно сохраняет `iptables-*.rules`, `ipset-*.txt`,
`ip-rule-*.txt`, `config-hashes-before/after-*.txt` в `/root/backups` и
сравнивает хэши конфигов AWG до/после. Снимок `system-config-*.tar.gz`
включает `/etc/amnezia/amneziawg`, `/root/awg` и `awg-routing.sh`; он нужен
только для ручного восстановления. Если хэши конфигов вдруг отличатся, в
журнале будет предупреждение — это сигнал проверить, не вмешался ли другой
процесс.

---

## 6. Требования

* Linux, root, `node` >= 18 (у вас 20.20.2), `pm2`, `tar`, `curl`;
* свободное место: ~50 МБ на релиз, stage и бэкап;
* релиз 2.4.1 везёт `node_modules` (express, express-session, qrcode),
  поэтому первый запуск не зависит от npm-реестра;
* порт 3000 (или значение из `.panel_port`) должен быть свободен для панели;
  тестовый порт 3998–4099 — только на время проверки.

---

## 7. Откат на старую версию

Полный откат:

```bash
bash /root/servpanel-2.4.1/upgrade.sh --rollback /root/backups/servpanel-pre-update-*.tar.gz
```

Или из панели: **Обновление → Резервные копии → Откатить**.

Старая версия 1.0.0 использует свою cookie-аутентификацию, поэтому после
отката снова понадобится войти с тем же паролем. Данные и каскад не
затрагиваются.
