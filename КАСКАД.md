# 🔀 Каскад RU → EU: полная инструкция

Полное руководство по схеме **«вход в РФ + выход в Европу»**: как это работает,
как запустить из панели Servpanel, как настроить и как обслуживать.

Схема совместима с официальным [CASCADE.md](https://github.com/bivlked/amneziawg-installer/blob/main/CASCADE.md)
и собрана так, чтобы не редактировать `iptables` руками.

## 1. Что такое каскад и зачем он нужен

Каскад — это два сервера, связанные одним туннелем:

| Роль | Где стоит | Что делает |
|------|-----------|------------|
| **Вход (RU)** | Российский сервер | Клиенты подключаются сюда. Заблокированный трафик уходит дальше в EU. |
| **Выход (EU)** | Зарубежный сервер | Принимает туннель с RU и выпускает трафик в интернет. |

**Зачем:**

* IP российского сервера обычно доступен клиентам и не блокируется, а IP EU может быть
  заблокирован.
* Российские ресурсы (банки, Госуслуги, маркетплейсы, локальные сервисы) идут **напрямую**
  через RU-провайдера — быстро и без «подозрительного» зарубежного IP.
* Всё остальное (заблокированные сайты, мессенджеры, зарубежные сервисы) идёт **через EU**.
* Клиент видит один вход — RU-сервер. Вторая нога каскада полностью прозрачна.

Итог: один клиентский конфиг, а трафик сам делится на «РФ напрямую» и «всё остальное через EU».

## 2. Как это работает (внутренняя механика)

### 2.1 Два интерфейса на RU-сервере

* **`awg0`** — основной клиентский интерфейс (по умолчанию подсеть `172.16.17.0/24`).
  Именно к нему подключаются телефоны, ноутбуки и роутеры.
* **`awg1`** — транзитный туннель RU → EU. Его конфиг — это клиентский конфиг,
  созданный на EU-сервере (клиент `ru_host`). В него панель добавляет `Table = off`
  и удаляет строку `DNS`.

`Table = off` означает, что AmneziaWG **не прописывает** свои маршруты автоматически —
маршрутизацией занимается отдельный скрипт панели. Это ключевое условие схемы CASCADE.md.

### 2.2 Путь трафика клиента

1. Пакет клиента приходит на `awg0`.
2. В таблице `mangle` цепочки `PREROUTING` срабатывает правило:
   * если адрес назначения входит в `ipset ru` → **`RETURN`** (идём напрямую через WAN);
   * иначе → **`MARK --set-xmark 0x1`** (помечаем пакет).
3. Правило маршрутизации `ip rule fwmark 0x1 table 100` отправляет помеченные пакеты
   в отдельную таблицу **100**.
4. В таблице 100 прописан `default dev awg1` — трафик уходит в EU.
5. Для клиентской подсети включён `MASQUERADE` на выход в `awg1`, чтобы EU видел
   адрес туннеля, а не внутренний адрес клиента.
6. EU-сервер выпускает трафик в интернет.

### 2.3 Защита от петли

Маршрут до самого EU-сервера (endpoint) принудительно прописывается **через внешний шлюз
WAN**, а не через туннель. Иначе пакеты к EU уходили бы внутрь туннеля, который сам же
к EU и ведёт, — получилась бы петля. Скрипт определяет шлюз и интерфейс автоматически
через `ip route get`.

### 2.4 Список российских сетей (`ipset ru`)

* По умолчанию список берётся с `https://www.ipdeny.com/ipblocks/data/aggregated/ru-aggregated.zone`.
* Если этот источник недоступен — используется резервный из репозитория
  `bivlked/amneziawg-installer` (`cascade/ru.zone`).
* Скачанный список проверяется: должно быть **не менее 1000 корректных подсетей**.
  Если проверка не прошла, старый `ipset` не трогается.
* Список загружается в `ipset ru` (тип `hash:net`).
* Дополнительные сети РФ (например, корпоративные подсети) добавляются в тот же `ipset`.
* Обновление — автоматически каждые **5 минут** через `awg-routing.timer`.

### 2.5 Маршрутизация по интерфейсам

Правила создаются отдельно для каждого выбранного клиентского интерфейса
(обычно `awg0`). Подсеть берётся из `ip addr` этого интерфейса, поэтому схема работает
и если вы сменили подсеть AWG. Для каждого интерфейса:

* `mangle PREROUTING`: `RETURN` для `ipset ru`, затем `MARK 0x1` для остального;
* `nat POSTROUTING`: `MASQUERADE` при выходе в `awg1`.

### 2.6 DNS

Из `awg1.conf` строка `DNS` **удаляется**. Это требование CASCADE.md: DNS-запросы
не должны уходить через транзитный туннель, иначе разделение ломается.
Клиенты используют DNS, который прописан у них в клиентском конфиге `awg0`
(если на RU стоит AdGuard Home — он и отвечает). Само разделение работает
по IP-адресам назначения, а не по доменам.

## 3. Требования и что подготовить

**Серверы:**

* Два VPS: один в РФ, один в EU.
* ОС: Debian 12/13 или Ubuntu 22.04–26.04.
* `root`-доступ по SSH **по паролю** на удалённый сервер — мастеру установки
  нужен пароль для `sshpass` (ключи он не использует).
* Публичные IP обоих серверов (или домены, если EU доступен по домену).

**На EU-сервере:**

* Установлен AmneziaWG (вкладка **«Установка»** → AWG, обычный режим «Один сервер»).
  После установки появляется `/root/awg/manage_amneziawg.sh`.
* Открыт наружу порт AWG (обычно `39743` или `443`) **в UFW/iptables/provayder**.

**На RU-сервере:**

* Установлена панель Servpanel.
* Желательно установлен AmneziaWG обычным способом (клиенты уже созданы).
* Установлены `curl`, `ipset` (мастер из панели доставит их сам).

**Порты на удалённом сервере:**

* SSH — указанный вами порт (по умолчанию `22`).
* AWG — порт прослушивания из конфига EU.

> ⚠️ **Перед началом** сделайте резервную копию на RU-сервере
> (вкладка **«Администрирование»** → «Резервное копирование» → «Создать архив»).
> Панель настраивает только маршруты и `awg1`, но лишняя копия не помешает.

## 4. Вариант A. Установка с нуля из панели (мастер)

Этот путь ставит AmneziaWG **на оба сервера** и сразу собирает каскад.
Он удобен, если оба сервера «чистые».

### Шаги

1. Войдите в панель **на RU-сервере**.
2. Откройте вкладку **«Каскад»** → кнопку **«Настроить каскад»**
   (или **«Главная»** → мастер **«Установка VPN»**).
3. Пройдите шаги мастера:

   * **Что делаем:** выберите **«Установить с нуля»**;
   * **Роль этого сервера:** выберите **«Вход RU»** (тот сервер, на котором вы
     сейчас в панели, станет входом);
   * **Второй сервер:** IP удалённого EU-сервера, SSH-порт, root-пароль.

4. Нажмите кнопку запуска. Откроется прогресс во вкладке **«Установка»**,
   живой лог — `/var/log/awg_install.log`.

### Что делает мастер

1. Ставит `sshpass` и копирует установщик на удалённый сервер.
2. Разводит подсети: вход — `172.16.17.1/24`, выход — `172.16.61.1/24`.
3. Запускает независимую установку AmneziaWG на удалённом сервере
   (он перезагрузится несколько раз; на этот случай пишется `cron @reboot`
   для авто-продолжения).
4. Ждёт в логе удалённого сервера отметку `INSTALLATION DONE`.
5. На EU создаёт клиента `ru_host` и забирает его конфиг.
6. На RU сохраняет его как `/etc/amnezia/amneziawg/awg1.conf`, удаляет `DNS`,
   добавляет `Table=off`, ставит права `600`, поднимает `awg-quick@awg1`.
7. Создаёт `/root/awg/awg-routing.sh`, юниты `awg-routing.service` и
   `awg-routing.timer`, включает и запускает маршрутизацию.
8. Убирает за собой временные файлы авто-возобновления.

### После завершения

* Проверьте статус во вкладке **«Каскад»** → **«Проверить сейчас»**.
* Если панель писала, что нужно подождать — дождитесь нескольких перезагрузок
  и откройте вкладку заново.

> 💡 **Надёжнее запускать мастер именно с RU-сервера** в роли «Вход RU».
> Ветка автоматической установки для роли «Выход EU» в установщике
> неполная (см. [раздел 14](#14-известные-ограничения)) — при роли EU
> маршруты на втором сервере могут не собраться.

## 5. Вариант B. Готовый конфиг EU (рекомендуемый)

Этот путь используется, когда AmneziaWG **уже установлен** на обоих серверах.
Он самый предсказуемый: панель сама определяет подсеть клиентского интерфейса.

### Шаг 1. Создайте клиента на EU-сервере

По SSH на **EU-сервере**:

```bash
/root/awg/manage_amneziawg.sh add ru_host
cat /root/awg/ru_host.conf
```

Скопируйте **всё содержимое** `ru_host.conf` (секции `[Interface]` и `[Peer]`).
Имя `ru_host` менять не обязательно — это просто имя клиента.

> Если файл `ru_host.conf` не появился, значит AmneziaWG на EU не установлен
> или установлен без `manage_amneziawg.sh`. Установите AWG из панели на EU.

### Шаг 2. Вставьте конфиг в панель на RU-сервере

1. Вкладка **«Каскад»** → **«Вставить конфиг EU»**
   (панель сама включит экспертный режим и прокрутит к полю).
2. В карточке **«Шаг 1. Конфиг EU-сервера»** вставьте скопированный текст.
3. Либо пройдите мастер: **«Настроить каскад»** → **«Настроить туннель»** →
   роль **«Вход RU»** → **«Открыть вкладку»**.

### Шаг 3. Выберите интерфейсы и сети РФ

В карточке **«Шаг 2. Клиентские интерфейсы и сети РФ»**:

* Отметьте интерфейсы, чей трафик пойдёт в каскад — обычно **`awg0`**
  (галочка на `awg0`/`amn0` стоит по умолчанию).
* При необходимости заполните **«Дополнительные сети РФ»** — по одной подсети в строке,
  формата CIDR (`203.0.113.0/24`) или просто IP. Их трафик пойдёт **напрямую**,
  минуя EU.

### Шаг 4. Нажмите «✅ Настроить каскад»

Панель:

1. проверит конфиг (наличие `[Interface]`, `[Peer]`, `PrivateKey`, `PublicKey`,
   корректный `Endpoint` вида `host:port`);
2. уберёт из конфига строки `DNS` и `Table`, добавит `Table = off`;
3. запишет `/etc/amnezia/amneziawg/awg1.conf` с правами `600`;
4. удалит устаревший файл `awg-eu.conf`, если он был;
5. выполнит `systemctl enable --now awg-quick@awg1`;
6. сгенерирует `/root/awg/awg-routing.sh` и установит юниты `awg-routing.service`
   и `awg-routing.timer`;
7. сразу применит маршруты (запустит `awg-routing.service`).

### Шаг 5. Проверьте результат

Во вкладке **«Каскад»** нажмите **«Проверить сейчас»** и **«Проверить сейчас»**
в блоке здоровья. Разбор полей и проверок — в [разделе 6](#6-управление-из-панели-все-кнопки-и-что-они-делают).
Команды ручной проверки — в [разделе 8](#8-проверка-после-настройки).

## 6. Управление из панели: все кнопки и что они делают

Вкладка **«Каскад»** (в меню — **«Каскад RU → EU»**) состоит из нескольких карточек.
Часть карточек помечена классом `advanced-only` и видна только в **экспертном режиме**
(переключатель в шапке панели). Мастер «Настроить туннель» включает экспертный режим сам.

### 6.1 Карточка «Каскад в один клик»

| Кнопка | Что делает |
|--------|------------|
| **Настроить каскад** | Открывает мастер. Два режима: «Установить с нуля» (ставит AWG на двух серверах) и «Настроить туннель» (вставка готового конфига EU). |
| **Проверить сейчас** | Обновляет статус каскада и сразу запускает проверку здоровья. |
| **Вставить конфиг EU** | Открывает вкладку, включает экспертный режим и фокусирует поле вставки конфига EU. |

### 6.2 Карточка «Состояние каскада RU → EU»

Кнопка **🔄 Обновить** перечитывает состояние (запрос `GET /api/cascade/status`).
Показывает:

| Поле | Что означает |
|------|--------------|
| Конфиг awg1 | Найден ли `/etc/amnezia/amneziawg/awg1.conf` (или старый `awg-eu.conf`). |
| Туннель awg-quick@awg1 | Активна ли служба `awg-quick@awg1` (интерфейс поднят). |
| Рукопожатие с EU | Сколько секунд назад было последнее рукопожатие с EU-пиром. |
| Таймер маршрутов | Активен ли `awg-routing.timer` (автообновление каждые 5 минут). |
| Интерфейсы | Какие клиентские интерфейсы помечаются (`MARK 0x1`) в `mangle PREROUTING`. |
| Записей GeoIP (ipset ru) | Сколько сетей сейчас в `ipset ru`. |
| Правило fwmark 0x1 | Есть ли правило `ip rule fwmark 0x1 table 100`. |
| Маршрут таблицы 100 | Первый маршрут таблицы 100 (должен быть `default dev awg1`). |
| Endpoint EU | Адрес и порт EU-пира из `awg1.conf`. |

**Цветовая логика статуса:**

* 🔴 «Туннель EU не настроен» — нет `awg1.conf`.
* 🟠 «Туннель awg1 поднят, но не активен» — конфиг есть, служба не запущена.
* 🟠 «Туннель поднят, ожидание пира EU» — интерфейс есть, рукопожатия ещё не было.
* 🟢 «Каскад работает (обмен N сек. назад)» — рукопожатие было менее 150 секунд назад.
* 🔴 «Связь с EU потеряна (N сек. назад)» — рукопожатие старше 150 секунд.

### 6.3 Карточка «Проверка здоровья каскада»

Кнопка **🩺 Проверить сейчас** (запрос `GET /api/cascade/health`) проверяет 7 пунктов:

| Проверка | Условие «ок» |
|----------|--------------|
| Конфиг awg1 | Файл существует. |
| Туннель awg-quick@awg1 | Служба активна. |
| Рукопожатие с EU | Было менее 180 секунд назад. |
| Таймер маршрутов | `awg-routing.timer` активен. |
| Правило fwmark | Есть `fwmark 0x1`. |
| Маршрут таблицы 100 | В таблице 100 есть маршрут. |
| GeoIP ipset | В `ipset ru` больше 100 записей. |

**Итог «✅ Каскад в норме»** ставится, если выполнены три критичных пункта:
**конфиг + туннель + рукопожатие**. Остальное (таймер, правило, таблица, ipset)
показывается как справка и помогает найти проблему, но не делает статус «сломан».

**Telegram-уведомления.** Если в **«Администрирование» → «Telegram-уведомления»**
включены уведомления, панель раз в 5 минут проверяет каскад и присылает:

* ⚠️ сообщение при падении (не чаще одного раза в 30 минут);
* ✅ сообщение о восстановлении.

### 6.4 Карточка «Шаг 1. Конфиг EU-сервера» (эксперт)

Поле для вставки клиентского конфига, созданного на EU-сервере.
Используется кнопкой **«Настроить каскад»** из следующей карточки.

### 6.5 Карточка «Шаг 2. Клиентские интерфейсы и сети РФ» (эксперт)

* Список клиентских интерфейсов с чекбоксами (обычно `awg0`).
* Поле **«Дополнительные сети РФ»**.

| Кнопка | Что делает |
|--------|------------|
| **✅ Настроить каскад** | Записывает `awg1.conf`, поднимает туннель и применяет маршруты (см. [раздел 5](#5-вариант-b-готовый-конфиг-eu-рекомендуемый)). |
| **♻️ Обновить маршруты** | Запускает `/root/awg/awg-routing.sh` вручную: перечитывает список РФ, пересобирает `ipset` и правила. |
| **⛔ Отключить каскад** | Останавливает и отключает таймер/службу маршрутизации, удаляет правила `iptables`, `ip rule`, чистит таблицу 100 и удаляет `ipset ru`. **Файл `awg1.conf` и служба `awg-quick@awg1` остаются.** |

### 6.6 Карточка «awg1.conf на этом сервере» (эксперт)

* Показывает текущий транзитный конфиг.
* Кнопка **💾 Сохранить awg1.conf** проверяет, что в тексте есть `[Interface]`,
  делает резервную копию `awg1.conf.bak_<timestamp>`, записывает файл с правами `600`
  и перезапускает `awg-quick@awg1`.
* Обычно здесь ничего менять не нужно — это для тонкой настройки.

## 7. Как настраивать параметры каскада

### 7.1 Клиентские интерфейсы

Это интерфейсы, трафик которых должен уходить в каскад. По умолчанию это `awg0`.
Если у вас несколько клиентских интерфейсов (`awg0`, `awg2`, …), отметьте все, чьи
клиенты должны ходить через EU. Для каждого панель добавит отдельные правила
`mangle`/`nat` и возьмёт подсеть из `ip addr`.

> Интерфейс `awg1` (транзитный) **не нужно** отмечать никогда.

### 7.2 Дополнительные сети РФ

Поле **«Дополнительные сети РФ»** принимает:

* IPv4, например `203.0.113.5`;
* IPv4/CIDR, например `203.0.113.0/24`;
* несколько значений через пробел, запятую или точку с запятой.

Эти подсети добавляются в `ipset ru`, и их трафик идёт напрямую (`RETURN`), а не в EU.
Применяйте, если у вас есть корпоративная сеть, VPN-подсеть или сервис, который должен
ходить напрямую.

Некорректное значение вызовет ошибку **«Некорректная подсеть в „дополнительных сетях РФ“»**.

### 7.3 Список российских сетей

Обновляется автоматически из `ipdeny` (резерв — `bivlked/amneziawg-installer`).
Менять источник из панели не нужно. Принудительное обновление — кнопкой
**«♻️ Обновить маршруты»**. Руками можно положить список в `/root/awg/ru.zone`
(формат — по одной подсети в строке).

### 7.4 Транзитный конфиг `awg1.conf`

Содержит:

* `PrivateKey` клиента `ru_host` (создан на EU);
* `Address` — адрес RU в транзитной подсети EU (например, `172.16.61.2/24`);
* `Table = off`;
* `[Peer]` с `PublicKey` EU и `Endpoint = EU_IP:PORT`.

`DNS` не должно быть в этом файле. Панель удаляет его автоматически.

### 7.5 Расписание обновления маршрутов

`awg-routing.timer` обновляет список и правила:

* при загрузке — через 30 секунд;
* далее — каждые 5 минут.

Расписание задано в юните `/etc/systemd/system/awg-routing.timer`
(если делать вручную из панели-установщика — там `OnCalendar=01:00` раз в сутки).

## 8. Проверка после настройки

Выполните на **RU-сервере** по SSH:

```bash
# Туннель поднят?
systemctl status awg-quick@awg1 --no-pager

# Есть ли рукопожатие с EU?
awg show awg1 latest-handshakes

# Список РФ и его размер
ipset list ru | head
ipset list ru | grep -c '^[0-9]'

# Правило и таблица маршрутизации
ip rule show | grep 'fwmark 0x1'
ip route show table 100

# Правила mark и nat
iptables -t mangle -S PREROUTING | grep -E 'awg0|match-set ru|0x1'
iptables -t nat -S POSTROUTING | grep awg1

# Логи скрипта маршрутизации
journalctl -u awg-routing.service -n 50 --no-pager

# Сколько сетей в скачанном списке
wc -l /root/awg/ru.zone
```

**Что должно быть:**

* `awg-quick@awg1` — `active (exited)` или `active (running)`;
* в `latest-handshakes` — ненулевой timestamp;
* в таблице 100 — `default dev awg1`;
* в `mangle PREROUTING` — `RETURN` для `match-set ru dst` и `MARK --set-xmark 0x1`;
* в `nat POSTROUTING` — `MASQUERADE ... -o awg1`;
* `ru.zone` — тысячи строк.

**Проверка со стороны клиента:**

* зайдите на `https://ifconfig.me` — должен показать **IP EU-сервера**;
* откройте российский сайт (например, банк) — должен грузиться быстро, напрямую;
* `curl ifconfig.me` из туннеля и без него должны отличаться.

## 9. Обслуживание и обновление

* **Обновление списка РФ** — автоматически каждые 5 минут, вручную кнопкой
  **«♻️ Обновить маршруты»** или `sudo /root/awg/awg-routing.sh`.
* **Перезагрузка RU** — `awg-quick@awg1` включён в автозапуск, а `awg-routing.timer`
  отрабатывает через 30 секунд после загрузки. Ничего вручную поднимать не нужно.
* **Обновление панели на RU и EU** — сначала обновите **EU**, затем **RU**.
  Каскад при этом перезапускать не нужно: `awg1.conf` и правила сохраняются.
* **Смена ключей/конфига EU** — создайте на EU нового клиента, на RU вставьте его
  конфиг заново через **«Настроить каскад»**.
* **Смена клиентской подсети** — не требуется: скрипт определяет её из `ip addr`.
  Достаточно нажать **«Обновить маршруты»** после смены, чтобы правила пересчитались.

## 10. Типовые проблемы и решения

### Туннель `awg1` не поднимается

Проверьте `awg1.conf`: `Endpoint` должен указывать на реальный адрес EU, ключи —
совпадать с `ru_host` на EU. Смотрите вывод:

```bash
systemctl status awg-quick@awg1 --no-pager
journalctl -u awg-quick@awg1 -n 50 --no-pager
```

### Интерфейс есть, но рукопожатия нет

* порт AWG на EU закрыт файрволом или провайдером;
* неверный `Endpoint` или порт;
* ключи не совпадают (пересоздайте `ru_host` и вставьте конфиг заново);
* EU-сервер недоступен.

Проверьте доступность порта с RU:

```bash
nc -vz EU_IP PORT
```

### Каскад есть, но трафик не идёт через EU

Проверьте по очереди:

```bash
ip rule show | grep 'fwmark 0x1'      # правило есть?
ip route show table 100                # default dev awg1 есть?
iptables -t mangle -S PREROUTING       # MARK и match-set ru есть?
ipset list ru | head                   # ipset не пустой?
```

Чаще всего помогает **«♻️ Обновить маршруты»**.

### Российские сайты идут через EU

`ipset ru` пустой или список не скачался. Проверьте `/root/awg/ru.zone`
и наличие доступа в интернет. Запустите **«Обновить маршруты»**.
Также убедитесь, что в дополнительных сетях РФ нет ошибок.

### Всё идёт напрямую, каскад не работает

Не отмечены клиентские интерфейсы или у них другая подсеть. Переоткройте
**«Шаг 2»** и нажмите **«Настроить каскад»** заново. Проверьте, что в
`mangle PREROUTING` есть правила именно для вашего интерфейса.

### Панель пишет «Связь с EU потеряна», но интернет через EU работает

Рукопожатие в WireGuard/AmneziaWG обновляется при трафике. Если трафика не было
дольше 150 секунд, статус может временно показать «потеряна». Дайте немного
трафика (откройте сайт) и обновите состояние. Если рукопожатие не появляется —
это реальная проблема, см. выше.

### «Все идёт напрямую» после перезагрузки

Подождите ~30–60 секунд: маршруты применяются таймером после загрузки. Если не
помогло — `systemctl restart awg-routing.service` или кнопка **«Обновить маршруты»**.

### Клиенты не резолвят домены

DNS в `awg1.conf` удалён намеренно. DNS должен быть в клиентском конфиге `awg0`
(например, AdGuard Home на RU). Проверьте DNS у клиента, а не в транзитном туннеле.

### Мастер установки застрял

Смотрите `/var/log/awg_install.log` на обоих серверах. Установщик может
перезагружать серверы — это нормально. Если процесс прервался, авто-продолжение
поднимется через `cron @reboot`.

## 11. Отключение и полное удаление

### Отключить маршрутизацию (конфиг остаётся)

Кнопка **«⛔ Отключить каскад»**:

* останавливает и отключает `awg-routing.timer` и `awg-routing.service`;
* удаляет правила `mangle PREROUTING` с `0x1` и `match-set ru dst`;
* удаляет `nat POSTROUTING` с выходом в `awg1`;
* удаляет `ip rule fwmark 0x1`;
* очищает таблицу 100;
* удаляет `ipset ru`.

Файл `awg1.conf` и служба `awg-quick@awg1` **не удаляются**. Клиенты снова ходят
напрямую (или как было настроено для `awg0`).

### Полностью снять каскад

По SSH на RU-сервере:

```bash
systemctl disable --now awg-quick@awg1
rm -f /etc/amnezia/amneziawg/awg1.conf
rm -f /root/awg/awg-routing.sh /root/awg/ru.zone
rm -f /etc/systemd/system/awg-routing.service /etc/systemd/system/awg-routing.timer
systemctl daemon-reload
```

На EU-сервере при желании удалите клиента `ru_host`:

```bash
/root/awg/manage_amneziawg.sh del ru_host
```

## 12. Файлы, юниты и пути

| Путь | Назначение |
|------|------------|
| `/etc/amnezia/amneziawg/awg1.conf` | Транзитный туннель RU → EU (`Table = off`, без `DNS`). |
| `/etc/amnezia/amneziawg/awg-eu.conf` | Устаревшее имя того же конфига; панель удаляет при настройке. |
| `/root/awg/ru.zone` | Скачанный список российских сетей. |
| `/root/awg/awg-routing.sh` | Скрипт построения `ipset`, `ip rule`, таблицы 100 и `iptables`. |
| `/root/awg/awg-routing.lock` | Файл блокировки, чтобы обновления не наложились. |
| `/etc/systemd/system/awg-routing.service` | Запуск скрипта маршрутизации. |
| `/etc/systemd/system/awg-routing.timer` | Автообновление каждые 5 минут. |
| `awg-quick@awg1` | Служба транзитного интерфейса. |
| `ipset ru` | Набор российских сетей. |
| `ip rule fwmark 0x1 table 100` | Правило отправки помеченного трафика в туннель. |
| Таблица маршрутизации `100` | `default dev awg1`. |

## 13. Безопасность

* Root-пароль удалённого сервера используется только на время установки
  и **не сохраняется** в панели.
* `awg1.conf` содержит приватный ключ и записывается с правами `600`.
* При сохранении `awg1.conf` из панели создаётся резервная копия
  `awg1.conf.bak_<timestamp>`.
* Все действия пишутся в аудит-лог панели (`/var/log/awg_audit.log`).
* Не открывайте панель в интернет без необходимости; каскад работает
  независимо от доступности панели.

## 14. Известные ограничения

* **Автоматическая установка в роли «Выход EU» неполная.** В установщике
  `install_awg_stateful.sh` ветка для роли EU создаёт на удалённом сервере
  заготовку скрипта маршрутизации без содержимого. Поэтому:
  * либо запускайте мастер **на RU-сервере** в роли **«Вход RU»**;
  * либо используйте **вариант B** («Настроить туннель» с готовым конфигом EU).
* **В режиме «Установить с нуля»** маршрутизация жёстко привязана к интерфейсу `awg0`
  и подсети `172.16.17.0/24`. Режим «Настроить туннель» из панели гибче — он сам
  определяет интерфейсы и подсети.
* **Порог рукопожатия 150 секунд.** При отсутствии трафика статус может временно
  показывать «связь потеряна». Это не всегда реальная ошибка.
* **Список РФ — по IP, не по доменам.** Сервисы, у которых зарубежные IP/CDN,
  могут уходить через EU, даже если сайт российский. При необходимости добавьте
  нужные подсети в «Дополнительные сети РФ».

# Статус туннеля
systemctl status awg-quick@awg1 --no-pager

sudo /root/awg/awg-routing.sh

systemctl disable --now awg-quick@awg1 awg-routing.timer
